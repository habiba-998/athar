# Competition demo: the six-minute story

**One sentence:** *ATHAR transforms cybersecurity from identifying attack paths into understanding, comparing, and validating defensive decisions before implementing them.*

Everything shown is synthetic. Numbers come from `docs/evaluation/MERIDIAN.md` (generated by `scripts/meridian_report.py`, deterministic) and are pinned by tests, so they appear exactly as written. A longer Harbor-based walkthrough is kept in the appendix.

## Setup (10 minutes before)

1. Start ATHAR (README), open **http://localhost:5173** (or your verified public URL; see `DEPLOYMENT.md`). Never present a URL that `scripts/verify_deployment.py` has not passed.
2. *Environment* > **Import JSON** > `scenarios/meridian-enterprise.json`. Check: "Meridian Synthetic Enterprise (digital twin)", **71 attack paths**, chips *Synthetic data* and *AI narration: off*.
3. Window at least 1280 px wide. Have `docs/screenshots/` open as a fallback.
4. **Offline / failure fallback (works with no network and no browser):** `cd backend; python ../scripts/meridian_report.py` prints the same tables in a terminal, `docs/evaluation/MERIDIAN.md` is the same content, and the screenshots show every screen. The app itself needs no internet: fonts are self-hosted and the AI is off by default.

## Numbers on screen (pinned by tests)

Meridian baseline: **71 attack paths**, posture **66.2**, highest path **80.0**; evidence classes 1 validated / 22 observed / 44 inferred / 4 theoretical. Top recommendation `rec-remove_relationship-a01`: removes the stale helpdesk bastion login, eliminates **46 of 71** paths, impact low. Plans: smallest change **71 to 25** paths; reversible-only **7** paths, posture **26.0**; maximum reduction and minimum cut **0** paths at high impact. Sensitivity: posture **57.4 to 86.7**, top recommendation unchanged in **100.0%** of 16 trials, highest-scoring path in **43.8%**.

# Appendix: longer Harbor walkthrough (about 10 minutes)

Everything shown is synthetic. Every number below is from `docs/evaluation/RESULTS.md` and is pinned by tests, so it will appear exactly as written.

## Before you go on (do this 10 minutes earlier)

1. Start both servers (README). Open **http://localhost:5173**.
2. *Environment* tab → **Import JSON** → choose `scenarios/harbor-logistics.json`. You should see "Harbor Synthetic Logistics", 34 assets, 55 relationships.
3. Check the chips: **Synthetic data**, **AI narration: off**. Keep the window ≥ 1280 px wide. Have `docs/screenshots/` open as a fallback.
4. Optional fallback if anything misbehaves: *Environment → Load sample*, then re-import Harbor.

## 1. Frame it (30 s)
"Security tools list weaknesses. Attackers move along *access*. ATHAR models that access as a graph, shows what a compromised account can reach, and **simulates the fix before anyone touches production**. It's a prototype on synthetic data: no scanning, no exploitation, no predictions."

## 2. The environment (45 s): Dashboard
"Harbor Synthetic Logistics: a fictional company, 34 assets: help-desk and HR staff, developers, a DBA and an IT admin, service accounts, application and infrastructure servers, four databases, cloud resources. We assume two things went wrong: a **help-desk analyst was phished**, and the **internet-facing portal is exploitable**. Those are assumptions, not findings."
Point at: **42 attack paths**, 5 critical, 12 validated; the hero path drawn as a trace; posture **67.3**; the *Assets at risk* list. "The line style on each hop says how well it's supported: solid validated, dashed inferred, dotted theoretical, and that's *declared in the data*, not verified by us."

## 3. How an attacker gets in (90 s): Attack graph
Click a help-desk path. The graph isolates it. Read it: *Lina → Helpdesk group → Admin jump host → Orders API → service account → Customer PII database*. Point at **Helpdesk group can log in to Admin jump host: admin, no recorded business use**. Click **Explain this path**: evidence, template text, and the separate dashed "AI-generated narration (not evidence)" block, which says AI is off. "Nothing here depends on an AI."
Also show: *Show only selected path* off → the whole graph with the path highlighted.

## 4. The simulation (2 min): the core
*Recommendations* → the top card: **remove the Helpdesk group's admin login to the jump host** (priority 2,049.7, impact low, 37 paths eliminated, "No legitimate use is recorded", requires human approval). Click **Simulate this**, **Run**.
Say the numbers: **42 → 5 paths**, posture **67.3 → 22.8**, validated paths **12 → 2**, impact **low**, **no legitimate access lost**, exactly two assets affected. Show the severed traces (scissors) and that the live environment is untouched (Attack graph tab still lists 42).
"It cost us one stale permission." Then **disable** instead of remove: same security effect, **reversible**. Use **Undo last change**.

## 5. The honest part (2 min): residual risk
"We still have 5 routes, all from the internet-facing portal." Show *Residual risks*: **Customer web portal → Orders API server: 88.0, critical, validated.** "That link is business-critical: the portal *has* to call the orders API. If I let the tool cut everything, it will tell me to disconnect the portal, and it flags that as **high impact**."
Open `docs/evaluation/RESULTS.md` (or the slide): the *all-actions* plan reaches 0 paths **only** by cutting business-critical access; the **business-safe** plan stops at 2 paths with that 88.0 route left. "That residual needs a different control (WAF, validation, rate limiting), which ATHAR displays but doesn't model. We would rather tell you that than show a green dashboard."

## 5b. Measurement (90 s)
- "Is the recommendation any good? Within the model, with 1 / 2 / 3 removals ATHAR leaves **5 / 1 / 0** paths. A naive 'remove the most frequent relationship' heuristic leaves 5 / 5 / 5. Random relationships on attack paths leave about 36 / 30 / 27. The exhaustive optimum is 5 / 1 / 0. The graph's minimum cut is 3."
- "It isn't always optimal: on the sample, at two removals it leaves 6 where the optimum leaves 5."
- "And we tested our own assumptions: varying every weight ±30%, the **#1 recommendation never changed**, but the **absolute scores moved a lot**: the posture swung between 59.8 and 78.3. So: trust the structure, treat the numbers as a prioritisation aid." (`docs/evaluation/SENSITIVITY.md`)

## 6. Your own environment (45 s): Environment
*Relationships* tab: **Disable** one; the dashboard recomputes. **Add relationship** with the same source and target → the server rejects it ("self-loop") and nothing changes. **Undo last edit**.

## 7. Arabic (30 s)
Click **العربية**: RTL, mirrored graph and route traces, Arabic names throughout, Latin digits, Arabic typeface. Open a phone-width window: bottom navigation, readable top-down path.

## 8. Close (45 s)
"What's verified: the path engine matches an independent re-implementation on 60 random environments and both scenarios; results are bit-for-bit reproducible across runs, input order and processes; simulation never mutates the live model; 652 backend tests, 66 browser tests. What's experimental: the scoring weights, the impact levels, the AI narration. What we do **not** claim: prediction, real-world validation, compliance, or being better than existing products. We audited ourselves: it found and fixed three defects in the product (a posture index that improved as more assets were breached, non-reproducible output ordering, and an understated impact estimate) and one in our own test oracle, all listed in `docs/TECHNICAL_VALIDATION.md`."

## Questions to expect, with honest answers

| Question | Answer |
|---|---|
| Is there machine learning? | No. Deterministic graph analysis. Optional AI only narrates and is off by default. |
| How are weights chosen? | Documented assumptions. We measured their influence: structure is robust, absolute values are not. Calibration on real data is the top next step. |
| Is "validated" real? | It's a label supplied with the data, synthetic here. ATHAR never upgrades or verifies it. |
| How is it different from a scanner? | Scanners find weaknesses on hosts; ATHAR reasons about chains of access, including ones with no CVE, and simulates fixes. They're complementary. |
| Has it been tested on real systems? | No. Synthetic data only; no pilot. |
| Can an attacker use it? | It only reasons over a model you give it; no scanning, exploitation or credential handling. |
| How does it scale? | Random graphs up to 500 assets / 5,000 relationships analyse in under a second and recommend in about 10 s; results are capped (500 paths) and flagged when truncated. |
| Why did you flag your own defects? | Because a validation claim that hides its findings isn't one. |

## If something goes wrong
- *"Could not reach the ATHAR API"*: start the backend and press **Retry**.
- Numbers differ from this script: you are not on Harbor. *Environment → Import JSON → scenarios/harbor-logistics.json*.
- A browser problem: show `docs/screenshots/`, then run `python scripts/evaluate.py` in a terminal to show the numbers regenerate identically.
